# Reproducibility: from a fresh clone to a running demo

The target path:

```
git clone  ->  install dependencies  ->  configure environment  ->  start services
           ->  load ontology/data  ->  validate  ->  run tests  ->  run demo
```

Every step is one command of `scripts/dev.py` (standard library only, so it runs before anything is installed). On Linux/macOS `make <command>` is the same thing.

| # | Step | Command | Needs | Notes |
|---|---|---|---|---|
| 1 | Clone | `git clone ... && cd hc_ontology` | git | The repository no longer contains a virtualenv, caches or secrets |
| 2 | Install | `python scripts/dev.py setup` | Python 3.11+, network | Creates `venv/`, installs `requirements.txt` pinned by `constraints.txt` |
| 3 | Configure | (done by `setup`) | | Creates `.env` from `.env.example` with a generated `NEO4J_PASSWORD`; `OPENAI_API_KEY` stays empty |
| 4 | Check | `python scripts/dev.py doctor` | | Pass/warn/fail per prerequisite, with the fix |
| 5 | Start services | `python scripts/dev.py up` | Docker | Neo4j 5.26, waits until it answers Cypher. Optional: skip to use your own Neo4j |
| 6 | Load | `python scripts/dev.py load` | Neo4j | SHACL-gated, idempotent, then verifies node/relationship counts |
| 7 | Validate | `python scripts/dev.py validate` | | Parse, generator equals file, SHACL, projection plan; `--reasoner` needs Java |
| 8 | Test | `python scripts/dev.py test` | | the whole suite passes; no Neo4j, no API keys |
| 9 | Demo | `python scripts/dev.py demo` | | Offline tour; `demo --neo4j` also queries Neo4j |

`python scripts/dev.py quickstart` runs 2, 4, 7, 8, 9 in sequence and stops at the first failure. Steps 5 and 6 are separate because they need Docker.

## What each capability needs

| Capability | Python | Java | Docker/Neo4j | OpenAI key |
|---|:-:|:-:|:-:|:-:|
| Ontology, SHACL, SPARQL, tests, demo | yes | | | |
| OWL reasoner checks (6 tests, `validate --reasoner`) | yes | yes | | |
| Neo4j projection (`up`, `load`, `demo --neo4j`) | yes | | yes | |
| Natural-language queries, embeddings, GraphRAG, agent | yes | | yes | yes |

Without Java the 6 reasoner tests are skipped, not failed. Without an OpenAI key every endpoint that needs one fails with an error naming the variable (the application starts and logs a warning). The test suite always runs with a placeholder key and tracing off, so it never calls OpenAI or LangSmith and never uses a developer's real keys.

## Fresh clone to working system: assessment

Verified by copying the files git would contain (without `venv/`, `.env`, `.git` or caches) into an empty directory and running `python scripts/dev.py quickstart` with a new virtualenv. Results are recorded at the end of this file.

### Every step that could fail, and what happens now

| Failure point | Before | Now |
|---|---|---|
| Repository contained a Windows virtualenv (15,736 tracked files) | Clone was huge and unusable | Removed from the index; `.gitignore` excludes it |
| `.env.example` referenced but missing | Reader had to guess ~60 variables | Present; `setup` creates `.env` from it |
| `.env` values are placeholders like `<your-openai-api-key>` | Treated as real keys, giving confusing auth errors | Placeholders count as unset (`core/config.py`) |
| README described Ollama; code uses OpenAI | LLM features failed on first call | README, scripts, compose agree with the code |
| `pip` fails with `CERTIFICATE_VERIFY_FAILED` (corporate proxy, antivirus HTTPS scanning, Windows) | Install impossible without manual steps | `setup` detects it, installs `pip-system-certs` (OS certificate store) with the two PyPI hosts trusted for that one step, then retries with verification on. The insecure step is announced and limited to PyPI. Hash-pinned requirements would make it unnecessary; not done yet |
| Unpinned dependencies (`>=`) | Different versions on every install | `constraints.txt` pins the tested set (`pip install -r requirements.txt -c constraints.txt`); `dev.py lock` refreshes it |
| `pytest` mixed into runtime requirements | Production image carried test tools | `requirements-dev.txt` |
| Tests needed a real `OPENAI_API_KEY` | 7 tests failed on a fresh clone (found by this exercise) | Tests use a placeholder key; no network |
| Wrong Python version | Obscure import errors | `setup` and `doctor` check 3.11+; `.python-version` |
| Neo4j: Desktop-only, database name confusion (`hcontology`, `HC`, `neo4j` in different files) | Manual GUI steps; connection errors | Docker service in compose; one database name, `neo4j` (Community Edition has a single user database) |
| Compose referenced an Ollama service and a source bind-mount | `up` failed or exposed `.env` | Neo4j + API + Streamlit; API waits for Neo4j health; no bind mount |
| Compose defaulted/required secrets | Fake default password, or required an OpenAI key just to start | `NEO4J_PASSWORD` required (generated by `setup`); OpenAI key optional |
| Load order (`/neo4j/load`, then embeddings) undocumented | Silent empty results | `load` verifies the counts; embeddings are separate and optional |
| Java missing | Reasoner tests errored | Skipped with a reason; `doctor` warns |
| Port already used (Neo4j Desktop on 7687, another app on 8000) | Container fails to start | `NEO4J_BOLT_PORT`, `NEO4J_HTTP_PORT`, `API_PORT`, `STREAMLIT_PORT` |
| Docker not running | Raw error | `up`/`down` check and say so |
| Mixed CRLF/LF; `setup.sh` had CRLF and could not run | Shell script failed on Linux | `.gitattributes` fixes endings; `setup.sh` is a thin wrapper |
| Container ran as root | | Unprivileged user, healthcheck |
| CI only ran pytest | Fresh-clone path untested | CI runs `setup -> doctor -> validate --reasoner -> test -> demo`, a Neo4j job loads twice and verifies, and a Docker job builds the image and validates the compose file |

### Known remaining limitations

* **Docker and Neo4j were not exercised in this environment** (the Docker daemon was not running). `docker_compose.yaml`, the Dockerfile and the Neo4j load/verify path are written to be run by CI (the `neo4j` and `docker` jobs) and by you; the load logic itself is covered by tests against a recording driver.
* **First install needs network access** to PyPI. There is no offline wheelhouse.
* **`constraints.txt` was generated on Windows.** On Linux, packages that only exist there (for example `uvloop`) are unpinned; everything else is exact.
* **The generated Neo4j password is only for local development.** For anything shared, set your own and `API_KEY`; see [security-and-configuration.md](security-and-configuration.md).
* Natural-language, embedding and agent features were not exercised without an OpenAI key.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `doctor` says dependencies do not import | `python scripts/dev.py setup` |
| `setup` prints the TLS warning | Expected behind proxies/antivirus; it recovers by itself. If it still fails: `pip config list`, set `HTTPS_PROXY`, retry |
| `up` says the daemon is not running | Start Docker Desktop |
| `up` times out | `docker compose -f docker_compose.yaml logs neo4j`; check the port is free |
| `load` says `NEO4J_PASSWORD is not set` | Run `setup` (creates it) or set it in `.env` |
| `load` says authentication failed | The Neo4j volume was created with an older password. `python scripts/dev.py down --volumes` deletes the **development** database (the graph is rebuilt from RDF by `load`), then `up` again |
| `load` reports `REJECTED` | The RDF violates the SHACL shapes; the problems are listed. Nothing was written to Neo4j |
| `validate` says the committed schema or sample data differs from its generator | `python scripts/generate_hc_ontology.py` and/or `python scripts/generate_sample_data.py`, review the diff, commit |
| 6 tests skipped | Install Java to run the OWL reasoner tests |
| Natural-language endpoints fail with `OPENAI_API_KEY is not set` | Add a key to `.env` (optional feature) |

## Recorded result of the fresh-clone check

Environment: Windows 11, Python 3.11.8, Java present, **Docker installed but the daemon not running**, no `.env`, no virtualenv, network behind antivirus HTTPS scanning (pip's `CERTIFICATE_VERIFY_FAILED` occurred and was recovered automatically).
Procedure: the working tree was copied to an empty directory without `venv/`, `.env`, `.git` or caches, then `python scripts/dev.py quickstart` was run.

| Stage | Result |
|---|---|
| `setup` | virtualenv created; TLS fallback engaged; pinned dependencies installed; `.env` generated |
| `doctor` | all required checks PASS; Docker/Neo4j/OpenAI reported as optional |
| `validate` | `VALIDATION PASSED` (generator equals file; SHACL conforms; projection plan: 124 nodes, 58 classes, 476 relationships) |
| `test` | **all pass, 0 failed** (no count is recorded here: it changes with every commit; `python -m pytest --collect-only -q` gives it) |
| `demo` | completed (offline) |

The first run of this check **failed**: 7 tests needed a real `OPENAI_API_KEY` even though they never call OpenAI. That is fixed (the suite uses a placeholder key), and a second pristine run produced the result above.

Not exercised here: `up`, `load`, `demo --neo4j`, `docker compose up`, `docker build` (no running Docker daemon). They are covered by the CI `neo4j` and `docker` jobs, which have not yet run.
